
# AWS VPC (Virtual Private Cloud) 

## 1️⃣ 개요

**VPC**란?

> AWS 클라우드 내에서 사용자가 직접 구성하고 제어할 수 있는 **가상 네트워크(Virtual Network)**

- 사용자는 IP 주소 범위, 서브넷, 라우팅 테이블, 인터넷 접근 여부 등을 직접 설정 가능
    
- **온프레미스 데이터센터의 네트워크와 거의 동일한 방식으로 구성 가능**
    
- AWS의 모든 서비스는 **VPC 안에서 동작** (EC2, RDS, Lambda VPC 연결 등)
    

---

## 2️⃣ 기본 구성 요소

| 구성 요소                          | 설명                                            | 시험 포인트                           |
| ------------------------------ | --------------------------------------------- | -------------------------------- |
| **VPC**                        | 전체 가상 네트워크                                    | CIDR 블록(예: `10.0.0.0/16`) 지정     |
| **Subnet**                     | VPC 내 네트워크 분할 단위                              | 퍼블릭 / 프라이빗 서브넷 구분                |
| **Route Table**                | 트래픽 경로 지정 테이블                                 | 인터넷 게이트웨이(IGW), NAT 게이트웨이 등 연결   |
| **Internet Gateway (IGW)**     | 퍼블릭 서브넷에서 인터넷 접속 허용                           | IGW가 연결된 서브넷 = 퍼블릭 서브넷           |
| **NAT Gateway / NAT Instance** | 프라이빗 서브넷의 인스턴스가 인터넷 **아웃바운드** 접근 허용           | 인바운드는 ❌                          |
| **Security Group**             | 인스턴스 수준 방화벽 (Stateful)                        | 허용 규칙만 설정 가능                     |
| **Network ACL (NACL)**         | 서브넷 수준 방화벽 (Stateless)                        | 허용/거부 규칙 모두 설정 가능                |
| **Elastic IP (EIP)**           | 고정 퍼블릭 IP 주소                                  | 주로 NAT Gateway, Bastion Host에 연결 |
| **VPC Peering**                | 두 VPC 간 직접 통신 연결                              | Cross-Region도 가능 (비전이중)          |
| **Transit Gateway**            | 여러 VPC와 온프레미스 네트워크를 중앙 허브로 연결                 | 대규모 네트워크 구조에 적합                  |
| **VPC Endpoint**               | AWS 서비스(S3, DynamoDB 등)에 **프라이빗 네트워크로 직접 접근** | 트래픽이 인터넷으로 나가지 않음                |
| **Flow Logs**                  | VPC 트래픽 로깅                                    | CloudWatch / S3로 로그 저장           |

## 3️⃣ 서브넷 (Subnet)

- **VPC의 IP 범위를 나눈 작은 네트워크 영역**
    
- **AZ(가용 영역)** 단위로 존재 (하나의 서브넷은 반드시 하나의 AZ에 속함)
    
- 일반적으로:
    
    - **퍼블릭 서브넷:** IGW로 라우팅됨
        
    - **프라이빗 서브넷:** NAT Gateway 통해 외부로 나감
        

📘 **시험 포인트:**

> “서브넷이 인터넷에 연결되려면 IGW와 라우팅 테이블이 필요하다.”

---

## 4️⃣ 라우팅 (Routing)

- **라우팅 테이블(Route Table)** 은 각 서브넷에 연결되어 트래픽 방향을 결정함.
    
- 예시:
    

| 목적지(Destination) | 대상(Target)             |
| ---------------- | ---------------------- |
| `10.0.0.0/16`    | local (VPC 내부)         |
| `0.0.0.0/0`      | Internet Gateway (퍼블릭) |
| `0.0.0.0/0`      | NAT Gateway (프라이빗)     |

## 5️⃣ 보안 구성 요소

| 항목                  | **Security Group (SG)**                           | **Network ACL (NACL)**                       |
| ------------------- | ------------------------------------------------- | -------------------------------------------- |
| 정의                  | EC2 인스턴스 단위의 **가상 방화벽 (Instance-Level Firewall)** | 서브넷 단위의 **네트워크 방화벽 (Subnet-Level Firewall)** |
| 동작 계층               | OSI **4계층 (Transport Layer)** — TCP/UDP 포트 기반     | OSI **4계층** — IP + 포트 기반                     |
| 평가 시점               | 인스턴스로 들어오거나 나가는 트래픽 시점                            | 서브넷에 들어오거나 나가는 트래픽 시점                        |
| 적용 범위               | 인스턴스(ENI 단위)                                      | 서브넷 전체                                       |
| 기본 상태               | 모든 트래픽 **차단 (Deny All)**                          | 모든 트래픽 **허용 (Allow All)**                    |
| 항목                  | **Security Group**                                | **NACL**                                     |
| **Stateful (상태유지)** | ✅ 예                                               | ❌ 아니오                                        |
| **의미**              | 인바운드가 허용되면 해당 응답 트래픽은 자동으로 허용됨                    | 인바운드/아웃바운드 각각 명시적으로 설정해야 함                   |
| **예시**              | 포트 22 (SSH) 인바운드 허용 → 응답 트래픽은 자동 허용               | 포트 22 인바운드 허용 시, 아웃바운드도 따로 허용 규칙 추가 필요       |

트래픽 흐름:  
>**인터넷 → NACL → Security Group → EC2**

| 상황                                  | 적합한 보안 계층      | 이유                           |
| ----------------------------------- | -------------- | ---------------------------- |
| EC2 인스턴스 접근 제어 (예: 웹서버, DB서버 포트 제어) | Security Group | 인스턴스별로 세밀하게 제어 가능            |
| 서브넷 전체의 접근 제한 (예: 특정 IP 대역만 허용)     | NACL           | Subnet 경계에서 대역 단위 제어         |
| 특정 IP 차단 (블랙리스트)                    | NACL           | Deny 규칙 설정 가능                |
| DB 서버는 웹 서버에서만 접근 허용                | Security Group | 다른 SG 참조 기능 활용               |
| 보안 계층 분리 (이중 방어)                    | 둘 다 조합         | NACL은 대역, SG는 인스턴스 단위로 세밀 제어 |

📘 **시험 포인트:**

> - SG는 인바운드 허용 시, 아웃바운드는 자동 허용 (Stateful)
>     
> - NACL은 들어온 요청이라도 아웃바운드 규칙 별도 설정 필요 (Stateless)
>

## 6️⃣ 인터넷 연결 구조 요약

|목적|구성 요소|설명|
|---|---|---|
|**퍼블릭 인터넷 연결**|Internet Gateway (IGW)|EC2 → 인터넷 직접 통신|
|**프라이빗 아웃바운드만 허용**|NAT Gateway / Instance|내부에서만 인터넷 접근|
|**AWS 서비스 전용 프라이빗 통신**|VPC Endpoint (Interface / Gateway)|S3, DynamoDB 등과 인터넷 없이 연결|

## 7️⃣ 고급 네트워킹 구성

|기능|설명|시험 포인트|
|---|---|---|
|**VPC Peering**|두 VPC 간 직접 연결 (1:1)|트랜짓 불가 (VPC A↔B, B↔C여도 A↔C는 X)|
|**Transit Gateway (TGW)**|여러 VPC/온프레미스 네트워크를 중앙 허브로 연결|대규모 멀티 VPC 환경에 유리|
|**PrivateLink / Interface Endpoint**|특정 서비스(API 등)에 프라이빗 연결 제공|“S3 접근 시 인터넷 경유 없이 연결” 문제에 자주 등장|
|**Flow Logs**|트래픽 정보 로깅|보안/모니터링용|

## 8️⃣ IP 주소 체계

- **CIDR 블록:**
    
    - IPv4 예시: `10.0.0.0/16` → 65,536개 IP
        
    - IPv6 예시: `/56`, `/64` 등
        
- **AWS 예약 IP (5개):**
    
    - 네트워크 주소, 브로드캐스트, 게이트웨이 등  
        → 실제 사용 가능한 IP는 `총 개수 - 5`
        

📘 **시험 포인트:**

> “서브넷은 VPC의 IP 범위 안에서 만들어지며,  
> 각 서브넷당 5개의 IP 주소는 AWS가 예약해서 사용할 수 없다.”

---

## 9️⃣ 연결 예시 — 퍼블릭/프라이빗 혼합 구조

`[VPC: 10.0.0.0/16]  ├── 퍼블릭 서브넷 (10.0.1.0/24)  │    ├── EC2 (웹 서버)  │    └── Internet Gateway 연결  ├── 프라이빗 서브넷 (10.0.2.0/24)  │    ├── EC2 (DB 서버)  │    └── NAT Gateway 연결`

👉 퍼블릭 서버는 외부에서 접근 가능,  
👉 프라이빗 서버는 외부 접근 불가, 단 내부에서 업데이트 가능.

---

## 🔟 시험 핵심 포인트 (암기용 ✅)

✅ VPC는 AWS 내 가상 네트워크  
✅ **퍼블릭 서브넷 = IGW로 라우팅된 서브넷**  
✅ **프라이빗 서브넷 = NAT Gateway 통해 외부 접근만 허용**  
✅ SG는 Stateful, NACL은 Stateless  
✅ 서브넷은 AZ 단위로 존재  
✅ 각 서브넷당 5개 IP 예약  
✅ **VPC Endpoint (PrivateLink)** = 인터넷 안 타고 AWS 서비스 접근  
✅ **Transit Gateway** = 여러 VPC 연결용 중앙 허브  
✅ **VPC Peering** = 1:1 연결, 트랜짓 불가

## 💡 예제 문제 포인트

| 문제 유형                               | 정답 포인트                            |
| ----------------------------------- | --------------------------------- |
| “프라이빗 서브넷 인스턴스가 인터넷에 업데이트 요청만 하려면?” | ✅ NAT Gateway                     |
| “S3와 프라이빗 네트워크로만 통신하고 싶다.”          | ✅ VPC Endpoint (Gateway type)     |
| “서브넷이 인터넷에 접근하려면 무엇이 필요?”           | ✅ IGW + 라우팅 테이블                   |
| “EC2 인스턴스에 SSH 접근 허용하려면?”           | ✅ Security Group 인바운드 규칙 (22번 포트) |
| “두 VPC 간 통신을 설정하되 중앙 라우터 없이 연결하려면?” | ✅ VPC Peering                     |
