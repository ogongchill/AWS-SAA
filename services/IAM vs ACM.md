## 🔐 IAM 인증서 vs ACM 인증서 비교 (시험 대비용)

| 구분             | **IAM 인증서**                                                                                                        | **ACM (AWS Certificate Manager) 인증서**                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **관리 서비스**     | AWS Identity and Access Management (IAM)                                                                           | AWS Certificate Manager (ACM)                                                                                                            |
| **주요 목적**      | **개별 사용자 또는 계정 수준에서 수동으로 업로드한 인증서 관리**                                                                             | **AWS 리소스(ELB, CloudFront, API Gateway 등)에 자동 배포 및 갱신되는 인증서 관리**                                                                         |
| **발급/등록 방식**   | - 외부에서 직접 발급받은 SSL/TLS 인증서를 **수동 업로드** (`aws iam upload-server-certificate`)  <br>- AWS가 인증서를 발급해주지 않음             | - ACM이 직접 **공인 인증 기관(CA)** 를 통해 인증서 발급 가능  <br>- 또는 외부 인증서 가져오기(import)  <br>- 자동 갱신 지원                                                  |
| **자동 갱신**      | ❌ 수동으로 교체 필요                                                                                                       | ✅ 자동 갱신                                                                                                                                  |
| **사용 가능한 서비스** | - **CloudFront (이전 버전, 레거시)**  <br>- **Elastic Beanstalk (일부)**  <br>- **API Gateway의 edge-optimized 엔드포인트 (레거시)** | - **Application Load Balancer (ALB)**  <br>- **Network Load Balancer (TLS 지원 시)**  <br>- **CloudFront (권장)**  <br>- **API Gateway (최신)** |
| **관리 편의성**     | 낮음 — CLI나 콘솔로 수동 업로드 및 갱신 필요                                                                                       | 매우 높음 — ACM이 자동으로 관리                                                                                                                     |
| **비용**         | 무료 (단, 직접 인증서 발급 비용은 별도)                                                                                           | ACM 퍼블릭 인증서 무료                                                                                                                           |
| **시험 포인트**     | “직접 업로드한 인증서를 특정 리전에 저장해 사용한다” → IAM 인증서                                                                           | “로드 밸런서/CloudFront에서 ACM 인증서 첨부” → ACM 인증서                                                                                               |

---

## 🧠 한 줄 요약

> - **IAM 인증서:** 직접 업로드한 수동 인증서 (레거시, 관리 불편)
>     
> - **ACM 인증서:** AWS가 자동 발급/갱신하는 관리형 인증서 (현행 표준)
>     

---

## 💡 시험에서 자주 나오는 형태

| 문제 문장                                           | 정답 포인트                 |
| ----------------------------------------------- | ---------------------- |
| “HTTPS 리스너를 설정해야 하고, 인증서를 자동으로 관리해야 한다.”        | ✅ **ACM 인증서 사용**       |
| “외부에서 받은 인증서를 수동으로 업로드해야 한다.”                   | ✅ **IAM 인증서 사용**       |
| “Application Load Balancer에서 SSL/TLS를 적용하려 한다.” | ✅ **ACM 인증서 첨부**       |
| “쿼리 문자열, 호스트 기반 라우팅 필요”                         | ✅ **ALB + ACM 인증서 조합** |
| “Network Load Balancer에서 TLS 암호화 적용 (고정 IP 필요)” | ✅ **NLB + ACM 인증서 조합** |

---

정리하자면:  
**지금 AWS 시험 기준(2025년 SAA-C03)** 에서는 거의 모든 경우  
👉 **ACM 인증서 + ALB/NLB 조합** 이 정답입니다.  
IAM 인증서는 “예전 방식(레거시)”으로만 출제되거나, “수동 업로드” 키워드가 있을 때만 등장합니다.

# 🔐 SSL / TLS 인증서란?

## 1️⃣ 개념 요약

**SSL/TLS 인증서**는

> “웹사이트(서버)가 신뢰할 수 있는 주체임을 증명하고,  
> 클라이언트(예: 브라우저)와 서버 간 통신을 암호화하기 위한 디지털 신분증”

즉,

- **누구랑 통신하는지 확인(인증)**
    
- **데이터를 암호화해서 안전하게 주고받음(보안)**  
    하는 데 쓰입니다.
    

---

## 2️⃣ SSL vs TLS

|구분|SSL (Secure Sockets Layer)|TLS (Transport Layer Security)|
|---|---|---|
|개발 시기|1990년대 중반|SSL의 후속 표준 (현재 사용 중)|
|상태|더 이상 사용되지 않음 (Deprecated)|✅ 현재 표준 프로토콜|
|버전|SSL 2.0, 3.0|TLS 1.0~1.3|
|시험 포인트|“SSL/TLS”라고 함께 표현하지만 실제로는 **TLS**를 의미||

👉 **요약:**  
요즘 말하는 “SSL 인증서”는 **TLS 인증서**를 뜻합니다.  
(‘SSL’이라는 이름은 역사적으로 남아있는 표현이에요.)

---

## 3️⃣ 역할 — “무엇을 보장하나?”

|역할|설명|예시|
|---|---|---|
|**① 서버 인증 (Authentication)**|서버의 신원을 검증|브라우저가 연결하려는 `https://naver.com`이 진짜 네이버인지 확인|
|**② 데이터 암호화 (Encryption)**|통신 데이터를 암호화하여 도청 방지|로그인 비밀번호가 네트워크 중간에서 보이지 않음|
|**③ 데이터 무결성 (Integrity)**|전송 중 데이터 변조 여부 확인|중간자가 요청/응답 내용을 조작하지 못함|

---

## 4️⃣ 동작 방식 (핸드셰이크 과정)

1. **클라이언트 → 서버:**  
    “인증서 보여줘!”
    
2. **서버 → 클라이언트:**  
    “이게 내 인증서야 (CA에서 발급받았어).”
    
3. **클라이언트:**
    
    - 인증서 유효성 확인 (CA 서명 검증, 만료일 등)
        
    - 서버의 공개키로 세션키를 암호화해 전달
        
4. **서버:**
    
    - 비밀키(private key)로 복호화
        
    - 이제 두 쪽만 공유하는 세션키로 **암호화된 통신 시작!**
        

👉 이후의 모든 통신은 **대칭키 암호화(AES 등)** 로 처리되어 빠르고 안전합니다.

---

## 5️⃣ 인증서 구조 (시험에서 종종 등장)

|구성 요소|설명|
|---|---|
|**도메인 이름 (CN)**|예: `www.example.com`|
|**공개키 (Public Key)**|암호화에 사용되는 키|
|**인증 기관 (CA)**|인증서를 발급한 주체|
|**유효 기간**|시작일 ~ 만료일|
|**서명(Signature)**|상위 CA의 서명 (신뢰 사슬 형성)|

---

## 6️⃣ 인증서 발급 주체

|유형|발급 주체|특징|
|---|---|---|
|**공인 CA 인증서**|DigiCert, Let's Encrypt, GlobalSign 등|브라우저 기본 신뢰 목록에 있음|
|**자체 서명(Self-signed)**|직접 생성 (시험/내부용)|브라우저는 “주의 요함” 표시|
|**AWS ACM 인증서**|AWS가 대신 공인 CA를 통해 발급/관리|ELB, CloudFront, API Gateway에서 바로 사용|

---

## 7️⃣ AWS 환경에서의 TLS 활용

|서비스|인증서 적용 방식|
|---|---|
|**Application Load Balancer (ALB)**|HTTPS 리스너에 **ACM 인증서** 첨부|
|**Network Load Balancer (NLB)**|TLS 리스너에 **ACM 인증서** 첨부|
|**CloudFront**|HTTPS 배포 시 ACM 인증서 사용|
|**API Gateway**|커스텀 도메인 HTTPS 연결 시 ACM 인증서 사용|

---

## 8️⃣ 시험 포인트 요약 ✅

|문장|정답 포인트|
|---|---|
|“웹 트래픽을 암호화하려면 어떤 인증서가 필요한가?”|✅ **SSL/TLS 인증서**|
|“Application Load Balancer에 HTTPS 리스너 추가”|✅ **ACM 인증서 첨부**|
|“사용자와 서버 간 데이터 암호화 보장”|✅ **TLS** 프로토콜|
|“서버 신원을 검증하고 데이터 무결성을 보장”|✅ **SSL/TLS 인증서 역할**|
|“자체 서명 인증서 사용 시 경고 발생”|✅ 브라우저 신뢰하지 않음|
|“자동 갱신되는 AWS 인증서 서비스”|✅ **ACM (AWS Certificate Manager)**|

---

## 💬 한 줄 요약

> SSL/TLS 인증서는 **서버 신원 증명 + 통신 암호화**를 위한 디지털 신분증이며,  
> AWS에서는 **ACM이 이를 자동 발급·갱신하고**,  
> **ALB/NLB/CloudFront** 등에 붙여 HTTPS 보안을 제공합니다. ✅
