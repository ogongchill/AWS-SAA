
# Patch Manager vs Run Command
---

## Patch Manager

> “운영체제 패치 자동화 도구”

- EC2 인스턴스 및 온프레미스 서버의 **OS 보안 업데이트를 자동화**.
    
- **Patch Baseline**이라는 기준을 만들어, 어떤 업데이트를 적용할지 정의.
    
    - 예: “Critical/Important 보안 패치만 적용”
        
- **Maintenance Window**와 연동하여 정해진 시간대에 패치 실행.
    
- 결과는 **Patch Compliance Report**로 확인 가능.

적합한 상황:
- 주기적으로 OS/보안 패치를 유지해야 할 때
- 컴플라이언스(PCI-DSS, ISO 27001 등) 기준 준수 필요할 때

---

## Run Command

> “수동 명령 실행 도구”

- 지정된 EC2/온프레미스 인스턴스에 **명령 또는 스크립트를 즉시 실행**.
- Bash / PowerShell / Python 등 어떤 명령이든 가능.
- 긴급 패치, 로그 수집, 설정 변경, 커스텀 앱 배포 등 다양하게 활용.

적합한 상황:
- **긴급 패치 / 임시 명령 / 서드파티 소프트웨어 업데이트**
- **운영 중 실시간 작업 (서비스 재시작, 로그 확인 등)**

---


| 상황                         | 권장 도구             | 이유            |
| -------------------------- | ----------------- | ------------- |
| 매달 정기적인 OS 보안 패치           | **Patch Manager** | 자동화 및 리포트 지원  |
| 특정 패키지(서드파티 앱)만 긴급 업데이트    | **Run Command**   | 커스텀 명령 가능     |
| 비표준 환경(사설 레포지토리, 독립 설치 파일) | **Run Command**   | 자유도 높음        |
| 규정 준수 보고서가 필요한 기업 환경       | **Patch Manager** | 컴플라이언스 리포트 생성 |
| 1회성 테스트 / 진단 명령 실행         | **Run Command**   | 단발성 작업에 최적    |

| 항목                       | **Patch Manager**                              | **Run Command**                                  |
| ------------------------ | ---------------------------------------------- | ------------------------------------------------ |
| **주요 목적**                | OS 및 소프트웨어 **패치 자동화**                          | 임의의 **명령 스크립트 실행**                               |
| **대상 범위**                | OS 패키지, 커널, 보안 업데이트 등                          | Shell/Bash/PowerShell 명령, 사용자 지정 스크립트            |
| **자동화 수준**               | **높음** – 사전 정의된 패치 기준, 스케줄 기반 적용               | **낮음** – 관리자가 직접 명령 작성 및 실행                      |
| **대표 문서 (SSM Document)** | `AWS-RunPatchBaseline`                         | `AWS-RunShellScript` / `AWS-RunPowerShellScript` |
| **사용 방식**                | Patch Baseline(기준) + Maintenance Window로 정기 적용 | 수동 또는 스크립트를 지정해 임시 실행                            |
| **롤백/보고서**               | 패치 컴플라이언스 리포트 제공                               | 단순 명령 결과 로그만 제공                                  |
| **주요 사용 목적**             | 주기적 OS 보안 패치 및 컴플라이언스 유지                       | 긴급 명령, 커스텀 소프트웨어 배포, 로그 수집 등                     |
| **대상 관리 방식**             | 태그, 인스턴스 그룹 기반                                 | 인스턴스 ID 또는 태그 기반                                 |
| **예시 문서 실행**             | `AWS-RunPatchBaseline`                         | `AWS-RunShellScript`                             |
| **UI 통합 위치**             | Systems Manager → **Patch Manager 콘솔**         | Systems Manager → **Run Command 콘솔**             |
