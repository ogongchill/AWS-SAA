
# 배스천 호스트 - Bastion Host

>Private Subnet(프라이빗 서브넷) 에 있는 서버에 안전하게 접근하기 위한 중간 관문(게이트웨이) 역할을 하는 EC2 인스턴스
>**“보안상의 이유로 직접 접근이 막힌 서버에 대신 들어가주는 대리 컴퓨터”** 

```
[Internet]
   │
   ▼
┌────────────┐
│      Public Subnet             │
│   Bastion Host (EC2)       │ ← SSH로 접근 허용 (22포트)
└────────────┘
          │
          ▼
┌────────────┐
│     Private Subnet            │
│   App / DB Server (EC2) │ ← 외부에서 직접 접근 불가
└────────────┘

```

|항목|설명|
|---|---|
|**목적**|외부에서 직접 접근할 수 없는 Private Subnet의 EC2 인스턴스에 안전하게 접근|
|**위치**|VPC의 **Public Subnet** (IGW 통해 인터넷 접근 가능)|
|**접근 방식**|SSH 또는 RDP (예: `ssh -i key.pem ec2-user@bastion-host`)|
|**보안 그룹 설정**|- 인바운드: **관리자 IP만 허용 (22/TCP)**- 아웃바운드: Private Subnet의 내부 IP만 허용|
|**운영 방식**|Bastion Host에 접속 후, 내부 서버로 **SSH Jump** 또는 **Session Manager** 통해 이동|
|**권장 구성**|- 최소한의 접근만 허용 (MFA + 제한된 키)- 로그 기록 (CloudTrail / CloudWatch)- AWS Systems Manager Session Manager로 대체 가능|
## 🧰 AWS에서의 배포 방식

### ✅ 직접 EC2로 구축 (전통적인 방식)

- Public Subnet에 EC2 인스턴스를 띄움
    
- 보안 그룹: 관리자 IP만 22번 포트 허용
    
- 그 EC2를 통해 Private Subnet 인스턴스로 SSH 터널 연결
    

### ✅ AWS Systems Manager Session Manager (모던 방식)

- EC2에 **SSM Agent** 설치 후,  
    AWS Console 또는 CLI에서 **Session Manager**를 통해 브라우저에서 직접 Private Subnet 인스턴스에 접근 가능
    
- **Bastion Host 자체가 필요 없어짐**
    
- 인터넷 접근 없이, IAM 권한 기반으로 안전하게 세션 연결
    

👉 시험에서는  
“Bastion Host를 제거하고 중앙화된 접근 제어를 구현하려면?”  
→ **AWS Systems Manager Session Manager** 가 정답이에요.

## 🛡️ 보안 베스트 프랙티스

| 항목           | 권장 설정                                     |     |
| ------------ | ----------------------------------------- | --- |
| **인바운드 규칙**  | SSH(22) 포트, 특정 관리자 IP만 허용                 |     |
| **아웃바운드 규칙** | Private Subnet CIDR 범위만 허용                |     |
| **접근 로그**    | CloudWatch + CloudTrail로 감사(Audit)        |     |
| **키 관리**     | SSH 키를 AWS Secrets Manager나 IAM으로 중앙화     |     |
| **대체 서비스**   | 가능하다면 Session Manager로 대체 (Zero-Trust 접근) |     |


# RDP
RDP 자격 증명은 ==원격 데스크톱 연결을 위해 사용자의 ID와 비밀번호==를 의미하며, 연결 오류 발생 시 **사용자 계정 설정 확인, 방화벽 설정 점검, 네트워크 연결 상태 확인, 또는 RDP 연결 파일 설정 변경** 등을 통해 해결할 수 있습니다. RDP 자격 증명 관련 문제는 가장 흔한 연결 실패 원인 중 하나입니다
